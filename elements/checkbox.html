Opt-in choices, multi-select lists, terms acceptance.

Do

  • Provide a label via the default slot (omit for a bare box).
  • Bind with v-model (controlled; parent owns state).
  • Use indeterminate for a parent over a mixed group.

Don't

  • Using variant/defaultChecked (the product override has neither).
  • Using a checkbox for mutually-exclusive choices (MRadio) or instant settings (MSwitch).

Decision flow

  1. Mutually-exclusive (pick one)? -> MRadio.
  2. Applies immediately (no Save)? -> MSwitch.
  3. Opt-in/consent/multi-select committed on Save? -> Checkbox.
  4. Parent over a partially-selected group? -> Checkbox + indeterminate.

Usage rules

checkbox
Use when: opt-in / multi-select / consent committed when the form is saved
Don't: for exclusive choices (radio) or instant settings (switch)
e.g. Send me updates; select rows/permissions
indeterminate
Use when: a parent checkbox represents a partially-selected group (shows a dash)
e.g. select-all over permission groups, tree/NOC pickers
disabled
Use when: option visible but not selectable in current state/permission
group
Use when: several related checkboxes laid out together (note: kit MCheckboxGroup is unused 0x; compose individual checkboxes)

Related
