Tabs

In-page tabbed navigation that switches between sibling views of ONE page (Overview / Performance / Logs) — NOT between-page routing (obs-sidebar / obs-breadcrumbs). Data-driven: the tabs attr is a JSON array of {key,label,count?,icon?,disabled?} (or a simple "A,B,C" list); content goes in one named slot per key; only the active pane shows. Class-based variants via the variant attr: line (default) · no-border (drops the bar rule, 21x dominant) · sticky (pins the bar in a scroll pane) · grey (tinted bar). A label can carry a count ("Alerts (12)") or a leading obs-icon. persist-key remembers the active tab in localStorage across reloads. Selecting is reflow-free (the active weight-500 width is reserved). Active tab = --primary (text + 4px underline, weight 500); inactive = --tabs-text-color; bar rule = --border-color. Render-faithful to the product MTab/a-tabs (line/top/default only — Ant card/vertical/size are unused and intentionally not built).

Do

  • Use for sibling views of the same context.
  • Use class='no-border' when the tabs sit on a card.
  • Append counts to the label string; keep labels short.
  • Build data-driven tab sets with v-for.
  • Use MPersistedTab where users return to a remembered tab.
  • Use `closable` + `addable` for an EDITABLE tab strip (e.g. the metric-explorer monitor tabs) — wire the `close` / `add` events to update your tab array; the × only shows when there is more than one tab.

Don't

  • Don't use tabs to navigate between separate pages — that's routing.
  • Don’t reach for card / vertical tabs (still unbuilt — not in the product); the supported editable pattern is `closable` + `addable` on the line tabs.
  • Don't build a separate count badge — the product appends '(N)' to the label.
  • Don't rely on the tabBarExtraContent slot to match the product — it's unused there.
  • Don’t expect obs-tabs to add/remove tabs itself — it emits close/add; the `tabs` array is data-driven, so the parent updates it (see obs-metric-picker for a component that manages this).

Decision flow

  1. Switching between sibling VIEWS of the SAME page (Overview / Performance / Logs)? -> obs-tabs. For BETWEEN-page navigation use obs-sidebar (primary) or obs-breadcrumbs (trail), NOT tabs.
  2. Tabs sitting on a card/panel that already has its own edges? -> variant="no-border" (the 21x dominant variant).
  3. A long scrolling pane where the tab bar must stay visible? -> variant="sticky".
  4. Tab bar on a plain surface that needs a tint? -> variant="grey".
  5. A tab label needs a live count? -> put it on the tab: tabs=[{"label":"Alerts","count":12}] renders "Alerts (12)" (not a separate badge).
  6. A tab needs a leading icon? -> add icon: {"label":"List","icon":"list"} (a product icon name; reuses obs-icon).
  7. Data-driven tab set? -> pass the whole array to tabs (JSON) or a simple "A,B,C" list; add/remove by changing it.
  8. Remember the user's last tab across reload / navigation? -> persist-key="<module>" (stores it in localStorage as <module>-tab).
  9. An EDITABLE tab set — the user CREATES / CLOSES tabs at runtime (the metric-explorer monitor tabs, worksheet/query tabs)? -> `closable` (a × per tab, shown only when >1) + `addable` (a + at the far right); they emit `close` {key} / `add` for you to update the `tabs` array. (Card / vertical tabs remain unbuilt — the product doesn’t use them.)

Usage rules

line
Use when: the default in-page tab strip — switching sibling sections of one page/entity.
Don't: to navigate between routes -> obs-sidebar / obs-breadcrumbs.
e.g. Monitor detail: Overview / Performance / Logs / Configuration.
no-border
Use when: the tabs sit inside a card/panel that already draws its own edges (the 21x dominant case).
Don't: as a page-level tab strip that needs the separating rule.
e.g. variant="no-border" on a widget/settings card.
sticky
Use when: a long scrolling detail/settings pane where the tab bar must stay in view.
Don't: short panes that don't scroll.
e.g. variant="sticky" inside a scroll container.
grey
Use when: the tab bar sits on a plain background and needs a subtle tinted strip.
Don't: the default page context (keep line).
e.g. variant="grey".
with-counts
Use when: a tab names a collection whose size matters (correlated Alerts / Logs / Metrics).
Don't: a static section with no count.
e.g. tabs=[{label:"Alerts",count:12}] -> "Alerts (12)".
with-icons
Use when: tabs read better with a leading glyph (List / Grid / Topology views).
Don't: text-only section tabs.
e.g. tabs=[{label:"List",icon:"list"}] (reuses obs-icon).
dynamic
Use when: the tab set comes from data/config (widget editor: Attributes / Metric / Style / Sorting / Column Setting).
Don't: a fixed known set (still fine, just inline the array).
e.g. bind tabs to your config array.
persisted
Use when: a module-level tab set the user returns to — remember their last tab across reloads.
Don't: transient/ephemeral tab sets.
e.g. persist-key="monitors" -> restores from localStorage on mount.
closable-addable
Use when: the user creates/removes tabs at runtime (monitor tabs, worksheet tabs)
Don't: a fixed set of sibling views (plain tabs)
e.g. closable addable → × on each (when >1) + a + that emits add

Known a11y issues

  • SF-001 focus ring.
  • Icon-only tabs need an accessible name.
  • Count updates while focused — announce.
  • low The × (close) sits inside the tab button — ensure a click on it does not also switch to that tab (it calls stopPropagation) and that its aria-label conveys which tab it closes for screen-reader users.
