Sidebar

The product's PRIMARY navigation — the left vertical MODULE rail (FlotoNavBar). Collapsed to 65px (brand mark + module icons) by default; HOVER-expands to 170px (ObserveOps wordmark + labels), or pin it open with `expanded`. Data-driven module list (icon + label, optional BETA tag); the active module highlights --primary-alt on --nav-selected-text-color, a hovered non-active item gets a --nav-hover-bg pill. Theme-aware. Pairs with obs-app-header (the horizontal top bar). NOT an in-module section menu (side-menu) and NOT sibling-view switching (obs-tabs).

Slots

  • brand — OPTIONAL wordmark text shown when expanded (default: ObserveOps). Only change it when the user explicitly asks for a different brand name.
  • logo — OPTIONAL override for the mark. By DEFAULT the sidebar already renders the built-in ObserveOps / Motadata brand mark — do NOT fill this slot unless the user explicitly wants a different logo.

Do

  • Keep the default ObserveOps / Motadata brand logo — it ships built-in. Only override slot="logo" (and `brand`) when the user EXPLICITLY asks for a different logo.
  • Feed the role/license-gated module set via `items`; set `active` to the current route's module key.
  • Pair it with obs-app-header (the horizontal top bar) for the full app chrome.
  • Let it hover-expand by default; only pin `expanded` when labels must always show.
  • Reuse the module glyphs from the product icon library (obs-icon names).

Don't

  • Don’t replace, remove, or blank the default logo — the sidebar comes with the ObserveOps brand mark by default; swap it only on explicit user request.
  • Don't use it for in-module section navigation (that's a side-menu) or sibling views (obs-tabs).
  • Don't hand-roll a module rail — reuse obs-sidebar.
  • Don't hardcode the panel colours — they're theme tokens (--nav-panel-bg / --nav-text-color).
  • Don't leave `active` unset on a real page.

Decision flow

  1. Switch between top-level product MODULES (Dashboards / Monitors / Alerts / …)? -> obs-sidebar (the left module rail).
  2. Navigate SECTIONS within one module (e.g. Settings sub-nav)? -> a side-menu, NOT the sidebar.
  3. Switch between sibling VIEWS of the SAME page? -> obs-tabs.
  4. Show location + a way up a hierarchy? -> obs-breadcrumbs.
  5. The horizontal global bar (logo / search / notifications / user)? -> obs-app-header (the sidebar's top-bar counterpart).
  6. A step-through create/setup flow? -> a stepper (steps), not the sidebar.

Usage rules

collapsed
Use when: the default resting rail — maximise content width; icons carry the modules, labels appear on hover
Don't: when labels must always be visible (pin it with `expanded`)
e.g. the 65px ObserveOps rail on a Monitors list page
expanded
Use when: labels should stay visible (wider viewports, onboarding) — set `expanded` to pin 170px
Don't: on narrow layouts where content width matters (leave it collapsed / hover-expand)
e.g. the pinned 170px rail showing Dashboards · Monitors · Alerts · …
active-item
Use when: always — set `active` to the current module key so the rail reflects the route
Don't: never leave `active` unset on a real page (the rail should always show where you are)
e.g. active="inventory" highlights Monitors as a --primary-alt pill
with-beta
Use when: a module is in beta — add beta:true to its item
Don't: for GA modules
e.g. SLO carries a BETA tag
logo
Use when: the user has EXPLICITLY asked to show a different brand — then override slot="logo" with their image and set the brand wordmark to their name.
Don't: by default. The sidebar ships with the ObserveOps / Motadata brand mark built in; an AI tool must NOT replace, remove, or blank it unless the user explicitly requests a custom logo.
Must: keep the default ObserveOps brand logo unless the user asks to swap it.
e.g. default (no slot) → the built-in Motadata donut mark. Custom brand only on request: <obs-sidebar ...><img slot="logo" src="acme.png"></obs-sidebar>.

A <nav aria-label="Primary"> landmark; each module is a link with aria-current="page" on the active one. Labels are visually hidden when collapsed but the link text remains in the accessibility tree (icons are decorative). Keyboard: links are tabbable and activate on Enter.

Known a11y issues

  • low SF-001 — a visible focus ring on nav items should be verified against the --nav-panel-bg / --nav-hover-bg surfaces in both themes.
  • low The rail hover-expands on pointer hover; keyboard/touch users rely on the collapsed icons (labels stay in the a11y tree) — pin `expanded` where always-on labels matter.
