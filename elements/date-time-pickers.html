Date & Time Pickers

The product's date/time selection family. The hero is TimeRangePicker (42×) — the observability time-range control (relative presets + absolute custom range). MDatePicker (10×, wraps a-date-picker) is the form date-time field, in practice ALWAYS used with show-time. MTimePicker wraps a-time-picker (12-hour) but is rarely used standalone. DateTimePopover is a lighter custom-range-only popover. TimeRangeSlider is a FUNCTIONAL, LINKABLE timeline scrubber — drive its window/band from a range picker via range-start/range-end.

Do

  • Use TimeRangePicker for chart/dashboard/log time windows.
  • Use :hide-custom-time-range when only relative windows are valid.
  • Use MDatePicker WITH :show-time for date-time form fields (the product norm).
  • Constrain selection with :max-selectable-range-days / :min-date where it matters.
  • Use size='lg' to line the range trigger up with 35px toolbar/action buttons, and show-range to print the resolved absolute window beside the pill.
  • LINK the slider to a range picker: read the picker's change fromMs/toMs and set them as range-start/range-end on the kind='slider' element so its window + band track the selection.
  • Read the change payload's resolved fromMs/toMs/from/to (range/preset kinds) or start/end (slider) instead of re-deriving the window yourself.

Don't

  • Don't hand-roll a relative-range dropdown — use TimeRangePicker.
  • Don't use a bare date picker for chart windows — that's TimeRangePicker's job.
  • Don't pass an empty string '' to MTimePicker/MDatePicker value (parses to an Invalid date) — pass null/undefined or a moment.
  • Don't assume card/inline calendar variants — the product uses the popup pickers only.
  • Don't set only one of range-start/range-end on the slider — the link needs BOTH (with end > start) or it stays in the default today ± 5-day window.
  • Don't read CustomEvent.detail directly — it's array-wrapped; read detail[0].

Decision flow

  1. Selecting a TIME WINDOW for charts/dashboards/logs (relative or absolute)? -> TimeRangePicker (the 42× hero).
  2. Want presets only (no absolute calendar)? -> TimeRangePicker :hide-custom-time-range (24×).
  3. A single date or date+time value in a FORM field? -> MDatePicker with :show-time (the product default).
  4. Just a time of day (e.g. a schedule)? -> MTimePicker (12-hour).
  5. A custom absolute from/to with NO presets, as a form field? -> DateTimePopover.
  6. A draggable timeline SCRUBBER over the current window? -> slider (TimeRangeSlider). LINK it to a range picker by feeding that picker's change fromMs/toMs into the slider's range-start/range-end.
  7. Constrain how far back/forward? -> :max-selectable-range-days (TimeRangePicker) or :min-date / :disabled-date (MDatePicker).
  8. Need the trigger to line up with 35px toolbar buttons, or to print the resolved absolute window? -> size='lg' and/or show-range on the range trigger.

TimeRangePicker
Use when: Selecting a TIME WINDOW for charts, dashboards, or log/metric explorers — relative presets (Last 5/15/30 Mins, Last 1/6/12/24/48 Hours, Today, Last Day, Last/This Week, Last/This Month) OR an absolute custom from/to range. This is the 42x hero control and the default answer for any observability time selection. Emits v-model { selectedKey, startDate, endDate, startTime, endTime }.
Don't: Don't use for a single date/date-time value in a form (use MDatePicker with :show-time), for a time-of-day schedule (MTimePicker), or when absolute custom ranges must be forbidden (use presets-only via :hide-custom-time-range). Don't hand-roll a relative-range dropdown — this is that control.
e.g. The dashboard/metric-explorer/log-search time-window control — click the '24h' pill to open the preset list, or choose Custom for a dual-month absolute range with From/To time selects.
presets-only
Use when: You need TimeRangePicker but absolute custom ranges shouldn't be allowed — pass :hide-custom-time-range to drop the 'Custom' option and expose only the relative presets. The dominant configured variant (24x). Use for widgets/contexts where only relative windows make sense.
Don't: Don't use when users legitimately need to pick an absolute from/to calendar range — use the full TimeRangePicker (Custom enabled). Don't reach for a separate component; this is just TimeRangePicker with one prop.
e.g. Widgets and panels where only relative rolling windows are valid — the preset list (Last 24 Hours, Last Week, etc.) with no absolute calendar.
excluded-options
Use when: You want TimeRangePicker but must hide specific preset keys that don't apply to the context — pass :excluded-options with an array of preset keys (e.g. ['today']) to drop just those presets while keeping the rest. A real, common variant (7x).
Don't: Don't use to remove the Custom range wholesale — that's :hide-custom-time-range (presets-only). Don't use if you need every preset; only reach for it when specific presets are invalid for the view.
e.g. A view where a preset like 'Today' is meaningless is dropped via :excluded-options="['today']" while the remaining relative windows stay available.
MDatePicker
Use when: A single date or date+time value in a FORM field. In the product it is ALWAYS used with :show-time (12-hour hh:mm A), so treat it as the date-TIME field with a calendar icon. Constrain with :min-date (7x) or :disabled-date, add :allow-clear for an × (9x).
Don't: Don't use for selecting a chart/dashboard time WINDOW — that's TimeRangePicker. Don't use for a bare time-of-day (use MTimePicker) or a presets-free custom range popover (DateTimePopover). Don't pass an empty string '' as the value — moment parses it to 'Invalid date'; pass null/undefined or a moment.
e.g. A maintenance-window start or schedule date-time field: <MDatePicker :show-time :min-date :allow-clear v-model> opening a single-month calendar with a 12-hour time spinner.
MTimePicker
Use when: Just a time of day (e.g. a daily run time / schedule), rendered as a 12-hour picker with a clock icon (allow-clear default true). Documented for reference — wraps a-time-picker.
Don't: Don't reach for it as a standalone control in practice: the product uses NO standalone time picker — time-of-day is entered via MDatePicker :show-time or inside the TimeRangePicker custom view (which uses a custom dropdown-based TimePicker). Don't use for a date or date-time value (MDatePicker) or a time window (TimeRangePicker). Don't pass '' as the value (parses to Invalid date).
e.g. A daily run-time / schedule time-of-day field (12-hour hh:mm A) — reference pattern; in real product code time-of-day arrives via MDatePicker show-time or the range custom view instead.
TimeRangeSlider
Use when: You need a draggable TIMELINE SCRUBBER over an existing time window — a tick rail with a DATE axis and two round handles that drag a band to reshape the selected window. It is FUNCTIONAL (kind="slider"): dragging emits change { startPct, endPct, start, end } and the handle tooltip shows the resolved datetime live while dragging. It is LINKABLE — pass range-start/range-end (epoch ms) to fit its window around, and snap its band to, a range picker's current selection (feed that picker's change fromMs/toMs in). The axis format adapts DD/MM ↔ HH:MM to the window length.
Don't: Don't use as the primary way to pick a window when users expect presets — pair it with (or LINK it to) TimeRangePicker rather than replacing it. Don't use in forms or for discrete date/time values. Only 2x — a specialized scrubber, not the default. Don't set only one of range-start/range-end (the link needs both, with end > start) or it stays in the default today ± 5-day window.
e.g. The dashboard timeline scrubber and the alert-correlation drawer — drag the two handles to reshape the visible window; or link it below a TimeRangePicker so the band tracks the picker's selection.
DateTimePopover
Use when: A custom absolute from/to range as a FORM field with NO presets — a lighter custom-range-only popover (built on MPopover + FlotoFormItem). Emits { startDate, endDate, startTime, endTime }.
Don't: Don't use when relative presets are wanted (use TimeRangePicker or presets-only) or for a single date-time value (MDatePicker). Rare (1x) — only when you specifically need an absolute from/to inside a form without the preset machinery.
e.g. The SLO correction-profile form — a custom-range-only from/to popover with no relative presets.

Known a11y issues

  • Preset rows are <a>/<div> — verify keyboard-reachable.
  • SF-001 focus ring.
  • Range error is shown as text.
  • Slider handles are drag-only (mousedown/mousemove) — no keyboard (arrow-key) operation or ARIA slider role; pair with the range picker for accessible selection.
