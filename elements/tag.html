Labels, metadata, removable selection chips.

Do

  • Use a plain tag for labels; :closable=true for removable chips; :rounded for pills.
  • Use MStatusTag for status/severity.

Don't

  • Using color variants (broken/illegible — F2).
  • Assuming info/neutral exist (F1); forgetting closable defaults to true (F5).

Decision flow

  1. User types/adds tags? -> LooseTags (input), not Tag.
  2. Shows status/severity? -> MStatusTag.
  3. Removable selection/filter chip? -> MTag :closable=true.
  4. Colored category label? -> MTag + tag-* class.
  5. Plain read-only label/metadata? -> MTag :closable=false.
  6. A COUNT / metric value (not a text label)? -> add `numeric` (JetBrains Mono, tabular figures).

Usage rules

plain
Use when: read-only label/metadata
Don't: if user can remove it (add :closable)
e.g. OS name, environment label
closable
Use when: a selection the user can dismiss (filters, picked items)
e.g. active filter chip with x
colored(tag-*)
Use when: color-coding categories
Don't: the color variant PROP (broken/illegible F2) — use the class
e.g. tag-red/tag-green/... category
status(MStatusTag)
Use when: reflecting a status string (up/down/critical/...)
e.g. monitor Up/Down
rounded
Use when: a fully-rounded pill look (cosmetic)
tag-red
Use when: Color-coding a negative/critical category label with a red tint — the most common colored tag (75×). Applied as a class (MTag class="tag-red"), legible in both themes.
Don't: Don't use the color `variant` prop (variant="error" is broken/illegible — F2). If the chip is driven by a status STRING (error/down/failed/critical/stopped/offline), use MStatusTag instead — its TAG_MAP resolves those to tag-red automatically.
e.g. A red-tinted 'Failed' job-run label or a 'Critical'/'Down' state chip in an inventory or alert grid.
tag-green
Use when: Color-coding a positive/success category with a green tint (57×). Apply as MTag class="tag-green".
Don't: Don't use variant="success" (broken — F2). For a status STRING (up/success/active/enabled/completed/online), let MStatusTag map it to tag-green instead of hand-applying the class.
e.g. A green 'Up'/'Enabled'/'Succeeded' chip in a monitor or job status grid.
tag-yellow
Use when: Color-coding a warning or transitional state with a yellow tint (15×). Apply as MTag class="tag-yellow".
Don't: Don't use variant="warning" (broken — F2). Note MStatusTag's TAG_MAP maps halted/paused/queued/aborted/starting to tag-yellow, but it lacks true severity 'warning' — for severity LEVELS use the Severity component, not this class.
e.g. A yellow 'Paused'/'Queued'/'Halted' job-run state chip.
tag-orange
Use when: Color-coding a caution/intermediate state with an orange tint (9×). Apply as MTag class="tag-orange".
Don't: Don't use variant="orange" (broken — F2). Prefer tag-yellow for transient/queued states and tag-red for hard failures; orange is for the in-between (suspended/fair).
e.g. An orange 'Suspended' monitor state or a 'Fair' quality-rating chip.
tag-purple
Use when: A rarely-used purple tint reserved for the 'unreachable' condition (1× — maps from --severity-unreachable). Apply as MTag class="tag-purple".
Don't: Don't reach for purple as a generic color — it carries the 'unreachable' meaning. Use tag-red/tag-green/tag-yellow for ordinary category coding, and the Severity component for severity levels.
e.g. A purple 'Unreachable' chip for a monitor that cannot be contacted (statusMap: unreachable → tag-purple).
tag-unknown
Use when: A neutral 'unknown' tint (2×) for indeterminate state — text is --severity-unknown on a light tint. Apply as MTag class="tag-unknown".
Don't: Don't use for a plain neutral metadata label — that's tag-primary. Reserve tag-unknown for genuinely unknown/indeterminate status.
e.g. An 'Unknown' status chip where a monitor's state can't be determined (statusMap: unknown → tag-unknown).
tag-primary
Use when: A neutral chip (NOT blue) — the default gray tag on --tag-bg-color, for read-only category/metadata labels and neutral states (49×). Apply as MTag class="tag-primary" (or forcePrimary on MStatusTag).
Don't: Don't use it for a semantic status — pick tag-red/green/yellow (or MStatusTag) so the color carries meaning. Don't confuse it with a blue/brand chip; it renders neutral gray.
e.g. A neutral device-category or environment metadata chip, or a 'Maintenance'/'Connected'/'Standby' state (statusMap maps those to tag-primary).
MStatusTag
Use when: The chip is driven by a status STRING (up/down/critical/paused/success/failed…) — MStatusTag looks the value up in TAG_MAP and renders the right tag-* color + capitalized label automatically. Always rounded and non-closable.
Don't: For true severity LEVELS (critical/major/warning/clear) use the Severity component — TAG_MAP lacks major/warning/clear and silently falls through to a plain gray tag (F7). For a static hand-picked color label, apply a tag-* class directly rather than routing through a status string. Beware F7: poweredoff→'Up', poweredon→'Down' (intentional inversion), and unmapped statuses render a silent plain tag.
e.g. A monitor's Up/Down state in the monitor status sidebar and instance grids: <MStatusTag :status="row.status" />.
used-count-pill
Use when: A rounded neutral COUNT chip — primary-text on a tint, always :rounded (48×) — for showing how many times something is used/referenced.
Don't: Don't use it to convey status or severity (use MStatusTag or a tag-* color class). It's a neutral count pill, not a semantic color, and it's distinct from the tag-* color classes.
e.g. A '3 used' count pill next to a template/credential in a usage list.
numeric
Use when: a COUNT or metric tag (log-type counts, used-counts, percentages) — the numeric font aligns figures
Don't: a text label tag (leave numeric off; text uses the normal font)
e.g. the Log tree counts (6.77 M, 653.32 K) render in JetBrains Mono; default 4px squarish, add rounded for a pill
