A focused task, dialog, or confirmation that must interrupt the flow.

Do

  • Use MModal for a focused dialog; FlotoConfirmModal for confirms.
  • Always include a footer Cancel (visible way out).
  • Use FlotoDrawer for long or record-contextual content.

Don't

  • Don't rely on a x or backdrop-click to close (disabled, F1).
  • Don't use a modal for content better inline or in a drawer.
  • Don't label actions Yes/OK — name the verb (Delete, Save).

Decision flow

  1. A yes/no or DESTRUCTIVE confirmation? -> obs-modal variant="confirm" (confirm-variant="error" for destructive).
  2. A focused short task/form that must INTERRUPT the flow? -> obs-modal (the default dialog).
  3. Long/complex content, or a panel CONTEXTUAL to a record (details/edit in place)? -> obs-drawer (side panel), NOT a modal.
  4. A full-screen flow / wizard? -> a page or obs-drawer, NOT a modal.
  5. Just a brief transient message? -> a notification/toast, not a modal.

Usage rules

dialog(MModal)
Use when: a focused task/form that interrupts the flow; short content
Must: include a footer Cancel (only visible way out — F1)
e.g. Edit/Filter/Note dialogs
confirm(FlotoConfirmModal)
Use when: confirm a yes/no or destructive action
e.g. Delete monitor? (error variant, Cancel/Delete); delete in CRUD lists, inline-name-edit, trap-profile
hide-footer
Use when: view-only content (no Save/Cancel); header x is the way out
e.g. metric-explorer Compare/Anomaly/Arithmetic/Outlier modals
scrollable-modal
Use when: long body that must scroll (lists/editors); wrap content in flex:1;min-height:0;overflow-y:auto (F3)
e.g. Compare metric, linked-records detail, widget JSON editor, column configurator
no-padding
Use when: content manages its own padding (editor/full-bleed)
e.g. log-collection profile list, view-query, LAMA integration, activation-code modal
drawer-instead
Use when: content is long or contextual to a record -> use FlotoDrawer (158x), not a modal
e.g. incident details, approval drawers
MModal
Use when: A focused, self-contained task or short form must interrupt the flow until the user finishes or dismisses it. Open via the trigger slot ({ open }); build your own header (title + close x) and a footer ({ cancel, success }); size with width/centered, use confirmLoading for async Save.
Don't: Don't use for yes/no or destructive confirmations (use FlotoConfirmModal), and don't use for long or record-contextual content like details/edit-in-place (use FlotoDrawer). Don't rely on the x or backdrop-click to close — both are disabled (F1), so always include a footer Cancel.
e.g. The metric-explorer Forecast / Anomaly / Compare / Arithmetic analysis modals, the Error modal, password-verify, chart capture, and linked-records detail dialogs.
FlotoConfirmModal
Use when: Confirming a yes/no or destructive action before it runs. Drive the open prop (boolean); use icon + message slots, successText/cancelText, variant="error" for destructive; listen to @confirm / @hide. Cancel sits left, the action right.
Don't: Don't use for a focused task or form that needs body input (use MModal). Don't label the actions Yes/OK — name the verb (Delete, Save). For a brief success/error message, use a notification instead of a confirm modal.
e.g. Delete confirmations across CRUD lists (paginated-crud), inline name edit, widgets, rediscover, domain-mapping, and trap-profile delete — Delete monitor? with error variant and Cancel/Delete.
restrict-width
Use when: You need a fixed wide modal (side-by-side comparison, wide tables) at 1020px regardless of the width prop. Apply overlay-class-name="restrict-width" (forces content min = max = 1020px); often paired with scrollable-modal.
Don't: Don't use for normal-width dialogs (use the width prop on MModal). Beyond a wide fixed modal, prefer a FlotoDrawer (the 85–96% full-screen pattern) rather than forcing 1020px.
e.g. The compare-metric and diff-view modals that show wide side-by-side content.
no-padding-modal
Use when: The content manages its own padding — a code editor, a full-bleed list, or an embedded form — and the default modal padding gets in the way. Apply overlay-class-name="no-padding-modal" (body → 8px) or no-padding-confrim-modal (body → 0).
Don't: Don't use for standard form/text dialogs that expect the default inset padding. This only strips padding; for scrolling long content combine with scrollable-modal, and for wide content with restrict-width.
e.g. The log-collection profile list, view-query, LAMA integration, and activation-code modals.
view-edit
Use when: [element/composition] a detail modal that toggles a read-only VIEW and an EDIT form (the product is-view pattern) — show the record with obs-key-value + an Edit button; on Edit swap to obs-input `block` fields + a Cancel/Save footer.
Don't: for a big multi-section record → a drawer or full page; for a one-shot create form the edit form alone is enough.
e.g. Edit monitor: view (Monitor/IP/Type/Polling) → Edit → the form → Save/Cancel back to view.
compare
Use when: [element/composition] a side-by-side comparison — a restrict-width (1020px) modal holding two (or more) obs-key-value panels (e.g. two monitors' CPU/Memory/Disk/Status).
Don't: for a single record's detail (a normal-width detail modal) or many rows to compare (a table).
e.g. Compare metrics: web-server-01 vs db-primary, colour-coded values + status tags.
