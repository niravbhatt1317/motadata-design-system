Gauge

A single ring gauge — the product's Monitor-Availability / Alert-Count dial. A track ring with a severity-coloured arc swept to value/total, a large mono number in the centre, and an optional label beneath. The DS chart library flags "gauge" as a CUSTOM-ENGINE type (data-only, no serializable config); this element IS that renderer, as a drop-in web component.

A KPI dial where a value reads against a group total and the fill is meaningfully coloured by a status — the availability/alert dials on the Alert-Summary dashboard. The arc length encodes value/total; the colour encodes severity.

Do

  • Lay one gauge per group member in a flex row and give them all the SAME total (the group total) so the arcs are comparable.
  • Pass a severity that matches the data's real status — the colour is information, not decoration.
  • Always pass total when you want an arc; total=0 draws only the track ring + centre number.
  • Add a label under each dial so the count has a name (Up, Critical, …).
  • Let the colours read from --severity-* / --primary tokens so the dial follows light + dark theme.
  • Show zero members too (value=0) to keep the group row complete and aligned.

Don't

  • Don't use a gauge for a time trend or many series — that's a line/area chart.
  • Don't mix different totals across dials in the same group row — the arcs stop being comparable.
  • Don't hardcode a fill colour or pick a severity that misrepresents the status.
  • Don't rely on colour alone — pair the dial with its label (and the centre number carries the value).
  • Don't stretch or size-hack the 82px ring for a big-number KPI; use a stat tile if you only need the number.

Decision flow

  1. Showing a value against a group total with a status colour (monitors up/down, alerts by severity)? -> obs-gauge.
  2. Showing a whole group at once? -> lay ONE obs-gauge per member in a flex row, each with the SAME total (the group total) and its own value + severity.
  3. No meaningful status colour for the figure? -> omit severity (falls back to --primary) — or reconsider whether a plain number/stat tile reads better.
  4. A trend over time, or many series? -> NOT a gauge; use a line/area chart from the data-viz family.
  5. A part-to-whole breakdown as a single figure (share of total across categories)? -> a donut/pie, not a ring of separate gauges.
  6. value can exceed total? -> fine, the arc clamps to a full ring; the centre number still shows the raw value.

Usage rules

availability-dial
Use when: showing monitor availability broken out by status — Up / Down / Unreachable / Maintenance, each against the monitor group total
Don't: for a single aggregate availability % with no per-status split (a stat tile reads better), or for a time trend
e.g. <obs-gauge value="160" total="172" severity="up" label="Up"></obs-gauge> in a 4-up row (Up 160 / Down 12 / Unreachable 0 / Maintenance 0), all total=172
alert-count-dial
Use when: showing alert counts broken out by severity — Down / Critical / Major / Warning, each against the alert group total
Don't: for a running alert timeline (use a chart) or a single total-alerts number (use a stat tile)
e.g. <obs-gauge value="13" total="37" severity="down" label="Down"></obs-gauge> in a 4-up row (Down 13 / Critical 3 / Major 1 / Warning 20), all total=37
severity-colour
Use when: the figure has a status meaning — pass the matching severity so the arc + number read via var(--severity-<level>) (down = red, critical/major = orange scale, warning = yellow, up = green, maintenance/unreachable = muted/purple)
Don't: hardcoding a colour or picking a severity that doesn't match the data's real status; if there's no status, leave severity empty (falls back to --primary)
e.g. severity="warning" paints the arc var(--severity-warning); severity="" paints it var(--primary)
empty-dial
Use when: a member has zero count — pass value="0" (and the group total) and it renders just the track ring + a centre 0, keeping the row aligned
Don't: hiding the zero member — the row is meant to show every status, including the empty ones
e.g. <obs-gauge value="0" total="172" severity="unreachable" label="Unreachable"></obs-gauge>
unsevered
Use when: the figure carries no status meaning — omit severity (or pass severity="") so the arc + centre number fall back to var(--primary); a neutral count-against-total dial when there is no Up/Down/Critical/Warning to encode
Don't: for any dial that DOES have a real status — Monitor Availability and Alert Count members always have a severity, so don't strip it there; and don't invent a severity just to get a colour
e.g. <obs-gauge value="48" total="120" label="In progress"></obs-gauge> — no severity attribute, arc paints var(--primary)
empty
Use when: value="0" or total="0" — the arc is suppressed and only the track ring + a centre 0 render; use it to keep a zero member visible and the group row aligned rather than dropping the dial
Don't: collapsing or hiding the dial when its count is 0 — the whole point of the row is to show every status including the empty ones; also don't fake a tiny arc for a 0 value
e.g. <obs-gauge value="0" total="172" severity="maintenance" label="Maintenance"></obs-gauge> — centre 0, track-only ring
full
Use when: value >= total — the fraction clamps to 1 and the arc sweeps the entire ring while the centre still shows the raw value; use it for an at-capacity / all-in-one-state member (every monitor up, or every alert at one severity)
Don't: reading the full ring as ">100%" — the arc caps at the ring, so pair it with the centre number when value exceeds total; and don't hand-cap the value before passing it in, the element clamps for you
e.g. <obs-gauge value="172" total="172" severity="up" label="Up"></obs-gauge> — full green ring, centre 172

A presentational readout — the value renders as real SVG <text> (screen-reader legible) and the label as real text beneath. Non-interactive: no focus, no hover, no keyboard affordance.

Known a11y issues

  • The arc encodes value/total by length + colour only; the ratio is not announced. The centre number gives the raw value but not the "of total" context to assistive tech.
  • Severity meaning is conveyed by colour (var(--severity-<level>)) — the label text must carry the status name so it isn't colour-only.
  • The SVG has no role/aria-label or title; a screen reader reads the bare number, not "160 of 172 Up".
