ObserveOps Elements

Installable, framework-agnostic Web Components — the genuine ObserveOps components, usable in any framework or plain HTML.

App shell

The authenticated app frame — NavBar (left rail, 50px, --nav-panel-bg) + Header (top, 55px) + the one scrolling content panel + a shell-level overlay layer (toasts, OmniBox, portals). The default shell for every in-app page. Toggle the chrome to see how the other shells (EmptyLayout, LoginLayout) drop regions.

Grid

The product's 12-column layout grid — MRow / MCol (wrappers over Ant a-row/a-col), ~540/~522 files. MCol :size is a span out of 12: 6 = half (the default form field), 12 = full, 3 = quarter, 4 = third, 2 = sixth. :gutter="16" for form rows; :gutter="0" only for structural wrappers; auto-size shrinks a column to its content.

Layout shells

The 4 route shells (chosen by the src/app.vue switcher + route.meta.layout override) + 2 content layouts that render inside Layout. They differ by chrome: Layout (nav + header + content, the default) · LoginLayout (bare sign-in) · EmptyLayout / PublicLayout (no chrome, padded) · MonitorHierarchyLayout (tree + content) · Settings two-pane (menu + content).

Page templates

The canonical page types ObserveOps repeats, as annotated wireframes inside the app frame — built from the composition recipes. List view (header + toolbar + table + pager) · Form view (field grid) · Detail view (header + tabs + panels) · Dashboard view (picker + time range + widget grid) · Explorer view (left tree/filter + query + results) · Wizard flow (stepper + step + Back/Next) · Graph / Canvas (tree + interactive node graph).

Panel behaviours

How panels & overlays open, move and resize. Drawer (slide-over, FlotoDrawer · 146) · Modal (a-modal · 37) · Collapsible (MCollapse · 19) · Expandable rows (9) · Resizable / split (splitpanes · ~3) · Affix / sticky · Dashboard tiles (vue-grid-layout · 5) · Bulk-action bar (fixed bottom · 2) · Popover (20+) · Full-screen / OmniBox overlay.

Screen regions

Inside the content panel a standard page stacks four regions top-to-bottom: Page header (required) → Toolbar / filter bar (optional) → Body (required) → Footer / pagination (optional). The body takes one of 6 content layouts — single column, two-pane, master-detail, dashboard grid, three-pane, chart-over-grid.

App Header

The GLOBAL top bar present on every authenticated page, and the COMPOSITION HOST for the App Chrome family: the brand/logo on the left, and on the right the interactive surfaces — global search, notifications, and the user account menu — plus a BUILD version tag. Two ways to fill the right side: (1) the INTERACTIVE composition (drop obs-command-palette, obs-notification-menu, obs-user-menu into the slots — each opens its own surface on click; this is how the product's bar works), or (2) the PRESENTATIONAL `actions` prop (declarative circular icon-buttons that fire an `action` event but open nothing — for a simple static header). App CHROME — a SEPARATE archetype from obs-page-header (the per-page title bar); pairs with obs-sidebar (the left module nav). Bar: 50px tall, --page-background-color, a --border-color bottom rule. Circular buttons 36×36 (--neutral-light; --primary when active); notification badge --secondary-red; avatar --primary.

Command Palette

The interactive header global-search omnibox — a search bar with a category picker (Metric/Log/Flow), a query field with a live suggestions dropdown, an Execute action (a red error icon on a parse error), a clear, and a time-range picker. For cross-app search / a command surface, NOT a list filter. Part of the App Chrome family; the turnkey form of the command-palette recipe.

Notification Menu

The interactive header notification panel — a bell + unread-count badge that opens a dropdown of alerts/system notifications with tabs, a scrollable list, and View all / Clear all. Drops into obs-app-header. Part of the App Chrome family; the turnkey form of the notification-dropdown recipe.

User Menu

The interactive header account menu — an avatar trigger that opens account links + a theme toggle + a danger Logout. Drops into obs-app-header’s `user` slot. Part of the App Chrome family; the turnkey form of the user-menu recipe.

Button

Primary action control. Triggers an operation or navigation.

Anomaly

AI/ML time series — the avg actuals with an anomaly confidence band, outliers leaving the band coloured by zone.

Charts

Every product chart variant, rendered from captured configurations.

Forecast

AI/ML time series — the projection continuing past the last actual interval as one spline with a widening confidence range.

Gauge

Single-value instruments — the solid-gauge dial and the numeric metro tile, ported from the product’s own SVG gauge.

Heat Map

Severity honeycomb of hexagonal cells (custom DOM, not engine-rendered): severity colours, a metric heat map coloured by the selected palette, and the with-host variant with monitor-type icons and host names.

Map

Geographic widget — country-intensity bubbles or labelled location points on the Highcharts world map, and the Online Map (Leaflet) variant; the same payload drives all renderers, like the product.

Pie chart

Share-of-whole views — pie and donut (the pie geometry with the product’s 70% inner size), with rotation, legend and data-label configuration.

Sankey

Flow diagram between source and destination — the captured Flow result rendered through the engine’s sankey type, like the product’s sankey view.

Time Series

Trend charts over time — line, area, vertical and horizontal bars, plus each stacked variant; single-counter and multi-counter forms.

Top N Views

The Top N widget’s non-chart Style views — one solid-gauge dial per monitor in a wrapping grid, the packed bubble cluster, and the treemap (Tree View). One payload drives all three, like the product’s Style picker.

Widget Card

The dashboard widget CHROME: a framed card with a grey header (title + a hover-revealed time badge + a hover-revealed kebab menu of Full Screen / Share / Edit / Clone / Remove), a body slot for any widget content (chart, gauge, heatmap, table…), the header as a drag handle, and a bottom-right resize grip. The card does not own its position — it emits card-dragstart / card-resizestart (composed, bubbling) so an obs-widget-grid parent can drive the layout, plus an action event for the kebab items.

Widget Grid

A live draggable / droppable / resizable dashboard grid — the framework-agnostic answer to vue-grid-layout. Slot in obs-widget-card children carrying data-x/data-y/data-w/data-h; the grid snaps each to a 12-column layout, pushes colliding cards down, compacts everything up under gravity, and auto-scrolls the page while you drag or resize a card past the fold. Emits layout-change with the settled positions.

Key-Value

The DS key-value / description list (obs-key-value) — the product's column-grid-view / overview-layout: a TRANSPOSED grid where columns become row labels (a tinted label cell) + the record's value. A single-record DETAIL view, common in widget overviews and detail panels. NOT a data table (it only shares the grid chrome) — for rows-of-records use obs-table.

Metric List

The DS metric / KPI list (obs-metric-list) — the product's vertical-value-grid. Each row is a PROMINENT value (a large number + a unit, right-aligned) followed by its label; no column header. Used by dashboard metric / KPI widgets. NOT a data table (it only shares the grid chrome) — for rows-of-records use obs-table.

Gauge

A single ring gauge — the product's Monitor-Availability / Alert-Count dial. A track ring with a severity-coloured arc swept to value/total, a large mono number in the centre, and an optional label beneath. The DS chart library flags "gauge" as a CUSTOM-ENGINE type (data-only, no serializable config); this element IS that renderer, as a drop-in web component.

Metric Picker

The metric-explorer selection panel — MONITOR tabs (closable + "+") → a "Select Monitor" GRID dropdown (reuses obs-grid-select: monitor table + checkboxes + View/Clear Selected) → Metric/Instance/Saved View tabs (obs-tabs) → search (obs-input) → a flat COUNTER list where each row is a ⊕ add · the raw counterName · a 4-way drag handle. It looks like a side menu but selects a VALUE (a counter to plot). Matched to the product metric-explorer / counter-list. Pick a monitor, search, ⊕ or drag a counter.

Severity Heatmap

The product's Infrastructure-Heatmap honeycomb (PlainHeatMap) — one hexagon per monitor, each filled with its severity colour, packed into a honeycomb grid. Hovering a hex raises the product tooltip (monitor name/IP + location + a severity pill). The DS chart library flags "heat-map" as a CUSTOM-ENGINE type (data-only, no serializable renderer); this element IS that renderer, ported 1:1 from the product's heatmap-single-group.vue — a border-coloured hex box with a 1px-inset severity cell (the thin outline), size x 1.1547 height and a size x 0.2885 honeycomb pull-up.

Date & Time Pickers

The product's date/time selection family. The hero is TimeRangePicker (42×) — the observability time-range control (relative presets + absolute custom range). MDatePicker (10×, wraps a-date-picker) is the form date-time field, in practice ALWAYS used with show-time. MTimePicker wraps a-time-picker (12-hour) but is rarely used standalone. DateTimePopover is a lighter custom-range-only popover. TimeRangeSlider is a FUNCTIONAL, LINKABLE timeline scrubber — drive its window/band from a range picker via range-start/range-end.

Divider

A thin rule that marks a semantic break between content — horizontal between stacked sections, vertical between inline items.

Banner

An inline notice / callout — a tinted surface with a status icon and a message. Intents: info (default, NEUTRAL), note (blue), success, warning, error. Persistent and in-flow — not a transient toast, not a blocking modal.

Filters

The product's filtering components, grouped by ARCHETYPE (not by the screen they sit in). Four distinct kinds: the Expression builder (nested AND/OR query builder), the Filter bar (inline chips), Quick filters (preset menu), and the Filter row (multi-selects + Reset/Apply). These are molecules; the Toolbars (organisms) compose them.

Color Picker

A colour picker (color-picker.vue) — a 20×20 swatch preview + chevron trigger opening an MPopover with a colour canvas (vue-color Sketch) + a 16-colour preset palette. Supports `transparent` (a swatch with a red diagonal line). Used for branding, widget, threshold and severity colour selection.

Dropdown

Dropdown picker — an input-like trigger that opens a popover menu. Single or multiple (Select-All header + Clear footer + “First (+N)” trigger), searchable, clearable (× on hover), text-only or read-only-pill triggers, disabled options, inline-add, and an optional two-pane description. Models the product’s FlotoDropdownPicker (510×/241 files).

Grid Select

The grid / table dropdown (obs-grid-select) — a dropdown whose menu is a searchable TABLE, not an option list: columns · per-row checkboxes · sortable header · a search box · a selected-count badge + View Selected / Clear Selected. Rich cells via a column `type` (text · status · severity · type-icons). The product's 'Select Agent / Select Monitor' picker (FlotoDropdownGridSelector + MonitorPicker/AgentPicker, ~70×). The open table floors at 720px wide so the View Selected / Clear Selected actions sit on one line and more columns are visible.

Input

Text input. A type-router (text/password/number/search/textarea/datetime). v-model is value+update. Almost always wrapped by FlotoFormItem for label+validation.

Icon

The reusable icon element (<obs-icon>) — renders a real product glyph from the shared library (_icons.js, extracted from src/assets/icons/icons.js; ~635 glyphs) by `name`. Accepts kebab (chevron-double-left) or camelCase (chevronDoubleLeft). Reactive: change `name` and the glyph swaps. Inherits the surrounding text color (currentColor) and takes a px/CSS-length `size`. Renders per-icon fill-rule/clip-rule, so glyphs with holes/overlaps (e.g. the theme-auto half-circle) draw correctly. Decorative by default; pass `label` for an accessible name. This is how any icon should be used across the DS — never hand-drawn/inlined SVG.

Link

Navigation control. Default renders a RouterLink (<a>); as-button renders an MButton that pushes the route on click. Only own prop is asButton; everything else passes through.

Logo

Renders a product monitor-type LOGO by name — the brand/technology marks from the product logo library (Assets → Logos). Two forms via `variant`: COLOUR (full-colour, default) and LINE (monochrome, inherits text colour); either falls back to the other, then to `no-icon`. The logo counterpart of obs-icon: use a LOGO for a technology/vendor/monitor-type; an ICON for a UI affordance. Names are case/space-insensitive + alias-friendly (docker→dockercontainer, aws→aws-cloud). ARCHITECTURE: a small BUILT-IN common set (~29) ships in the main elements bundle so obs-logo works standalone; the FULL library (250 colour + 195 line) loads from the separate OPT-IN `observeops-logos` bundle (one `<script>`), which the showcase site loads so every name renders. AI tools: the complete 445-name list is in this registry `names` — pick any of them; never invent a name.

Menu

The MMenu primitive (a vertical list of selectable icon+label rows, with dividers and danger/positive colours) catalogued in its own right, plus its action-surface usage: the Context/Action menu (FlotoGridActions — a '...' trigger opening an MMenu of actions).

Breadcrumbs

The location TRAIL (+ an optional back chevron): a path of crumbs (Reports / Compliance / PCI-DSS Audit) with the current (last) crumb in weight 500 and the ancestors as muted links. Shows where the user is and gives a one-click way up one or many levels. Data-driven `items`; separator is `/` (default) or a chevron. Lives in a page header (obs-page-header has a `breadcrumb` slot). NOT module switching (obs-sidebar), NOT sibling views (obs-tabs), NOT a graph-expansion trail.

Side Menu

The in-module SECTION navigation panel — a searchable, collapsible left menu. ONE element with a `mode` axis folding the product's four side-menu forms: sections (settings sub-nav, 20×), categories (dashboard picker, count tags), tree (Log/Topology N-level hierarchy with type icon + count badge), and list (report/saved-views flat list, optional ★ favourite). Data-driven via a recursive `items` model; optional top segmented `tabs` + a search box. The active leaf highlights --primary on --code-tag-background-color (sections adds a --primary left rule). NOT the module rail (obs-sidebar), NOT sibling views (obs-tabs), NOT the faceted checkbox filter (a vertical Filter). SIZING: the element is width:100% (fills its container) — set the container WIDTH per mode (sections ~15% / categories ~30vw / tree|list ~20%); see `sizing` + usageRules[mode].width.

Sidebar

The product's PRIMARY navigation — the left vertical MODULE rail (FlotoNavBar). Collapsed to 65px (brand mark + module icons) by default; HOVER-expands to 170px (ObserveOps wordmark + labels), or pin it open with `expanded`. Data-driven module list (icon + label, optional BETA tag); the active module highlights --primary-alt on --nav-selected-text-color, a hovered non-active item gets a --nav-hover-bg pill. Theme-aware. Pairs with obs-app-header (the horizontal top bar). NOT an in-module section menu (side-menu) and NOT sibling-view switching (obs-tabs).

Steps

A wizard/stepper — a numbered progress track through the ordered stages of a multi-step flow, showing which steps are done, which is current, and which remain.

Drawer

Slide-in side panel (from the right) for detail views, edit forms, and record-contextual content. The product's MOST-used overlay (FlotoDrawer 99x + FlotoDrawerForm 59x = 158x). Open via open prop or trigger slot.

Modal

Centered dialog over a dimmed backdrop. MModal (39x) is the base; FlotoConfirmModal (71x) is the confirm variant. Open via trigger slot or open prop. No x/backdrop-close (footer/Escape only).

NOC Player

The NOC / wallboard rotator chrome — a top bar that auto-cycles a set of dashboards on a countdown (logo · prev/title/next · countdown + play/pause + exit) over a body slot for the current dashboard. Self-contained playback: an internal timer advances; ←/→ step, space pauses, Esc exits. Part of the Playback & Timeline family. Watch it count down and rotate.

Timeline Scrollbar

The temporal navigator bar — batch (« ») and single-step (‹ ›) controls around a START–END time window of bucketed snapshots. Emits `shift {direction,batch}`; the consumer moves its window. Part of the Playback & Timeline family. Watch the console (shift events) as you click.

Data-Viz Tooltips

The product's chart & widget hover tooltips — a distinct family from MTooltip, owned by the chart layer (Highcharts TooltipBuilder, graph canvases, widget Vue components), not DS components. ~28 reference reproductions cover every mechanism.

Tooltip

Transient hover/focus label anchored to a trigger. The kit MTooltip is excluded and this Floto override ships instead, rendering through VTippy (not a-tooltip). trigger slot = anchor, default slot = content. Non-interactive — for interactive panels use Popover.

Checkbox

Single boolean toggle, usually with a label. Functional, fully-controlled.

Radio

One-of-many selection control. Use MRadioGroup with :options + v-model; as-button renders a segmented control. Standalone MRadio is unused.

Switch

Instant on/off toggle for a setting that applies immediately. Controlled.

Table

The product's primary data table. Resizable/reorderable/sortable columns, client + server paging, grouping, selection (with bulk-action bar), expandable detail rows, per-column cell slots. MGrid is the grid; FlotoPaginatedCrud is the fetch+paginate wrapper around it.

Tabs

In-page tabbed navigation that switches between sibling views of ONE page (Overview / Performance / Logs) — NOT between-page routing (obs-sidebar / obs-breadcrumbs). Data-driven: the tabs attr is a JSON array of {key,label,count?,icon?,disabled?} (or a simple "A,B,C" list); content goes in one named slot per key; only the active pane shows. Class-based variants via the variant attr: line (default) · no-border (drops the bar rule, 21x dominant) · sticky (pins the bar in a scroll pane) · grey (tinted bar). A label can carry a count ("Alerts (12)") or a leading obs-icon. persist-key remembers the active tab in localStorage across reloads. Selecting is reflow-free (the active weight-500 width is reserved). Active tab = --primary (text + 4px underline, weight 500); inactive = --tabs-text-color; bar rule = --border-color. Render-faithful to the product MTab/a-tabs (line/top/default only — Ant card/vertical/size are unused and intentionally not built).

Selected Pills

Teal key:value pills for selections inside a picker/multi-select. Truncates to max-items, then a "+N" pill opens a popover listing the rest.

Severity

The severity INDICATOR — a coloured dot (+ optional label + tooltip) for a severity LEVEL (down / critical / major / warning / clear / up / maintenance / unreachable / unknown / …). Distinct from MStatusTag, which maps status STRINGS to tag-* pills. Used 80×. Renders --severity-<level>; can take `severity` directly or resolve it live from a monitor (objectId / instance / counter) via DB workers.

Tag

Compact label for categorization or removable selections. Used as a plain tag; color variants are broken.

Tags Input

A multi-value pill input in two types. type="loose" — free-create teal pills (LooseTags / MSelect mode=tags; type + Enter, optional suggestions). type="select" — pick only from a fixed options list → neutral chips (MSelect mode=multiple). Both: removable pills + dropdown + chevron.

Page Header

The list/detail PAGE HEADER at the top of a page: an optional back button + the title (--primary-alt, weight 500) + an optional count pill on the left, and right-side actions (search / export / primary Add) via the default slot, over a --border-color bottom rule. Split from the product's Toolbars family. NOT the strip above a list/table (that is obs-toolbar) and NOT between-page navigation (obs-sidebar / obs-breadcrumbs). Supports an optional subtitle, a detail-header metadata strip (meta=[{label,value,icon?,status?}] with an accent stripe — the RUM/APM span-detail header), (detail/drawer header pattern) and a breadcrumb slot (drop obs-breadcrumbs). The global app top-bar (logo/search/notifications/user) is a SEPARATE archetype, not a page-header variant.

Toolbar

The control strip that frames a LIST/TABLE or a widget. Three compositions via `variant`: grid (default) — a strip ABOVE a grid with search (start slot) on the left and filter / column-chooser / primary Add (default slot) on the right; bulk — the floating SELECTION pill (a clear checkbox + "N items selected" + a divider + the bulk actions), shown once rows are selected, emits `clear`; widget — a widget header (title + a time-range pill + a kebab of actions) with rounded-top chrome. NOT the page title bar (obs-page-header) and NOT the global top bar (obs-app-header). Compose the contents from DS elements (obs-input, obs-button, obs-checkbox, obs-icon, obs-select).
