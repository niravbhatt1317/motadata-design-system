Logo

Renders a product monitor-type LOGO by name — the brand/technology marks from the product logo library (Assets → Logos). Two forms via `variant`: COLOUR (full-colour, default) and LINE (monochrome, inherits text colour); either falls back to the other, then to `no-icon`. The logo counterpart of obs-icon: use a LOGO for a technology/vendor/monitor-type; an ICON for a UI affordance. Names are case/space-insensitive + alias-friendly (docker→dockercontainer, aws→aws-cloud). ARCHITECTURE: a small BUILT-IN common set (~29) ships in the main elements bundle so obs-logo works standalone; the FULL library (250 colour + 195 line) loads from the separate OPT-IN `observeops-logos` bundle (one `<script>`), which the showcase site loads so every name renders. AI tools: the complete 445-name list is in this registry `names` — pick any of them; never invent a name.

Do

  • Use obs-logo for technology / vendor / monitor-type marks (they carry brand colour).
  • Names are case/space-insensitive — obs-logo name="Windows" and name="windows" both work; aliases resolve.
  • Leave `label` empty when the logo sits beside its own text; set it when the logo stands alone.
  • Compose it in lists/trees (obs-side-menu tree, monitor lists) via a `logo` field / <obs-logo>.
  • To render EVERY logo (not just the ~29 built-in), load the opt-in bundle once: <script src="…/@mtdt/observeops-ds-elements/dist/observeops-logos.js"></script>. The showcase site already does.
  • AI: choose the logo name from this registry `names` (all 445) — never invent one; unknown names fall back to no-icon.

Don't

  • Don't use obs-logo for monochrome UI affordances — that's obs-icon.
  • Don't hardcode a logo <img>/<svg> — reuse obs-logo so the library stays the single source.
  • Don't assume every one of the 242 is bundled — the curated ~114 covers common types; the rest fall back to no-icon.
  • Don't recolour a brand logo (they're intentionally full-colour).

Decision flow

  1. A technology / vendor / monitor-type mark that carries BRAND COLOUR (Linux, Docker, AWS, MySQL)? -> obs-logo.
  2. A monochrome UI affordance that should inherit the text colour (chevron, search, trash)? -> obs-icon, NOT obs-logo.
  3. The logo sits next to its own visible text (a menu row label)? -> leave `label` empty (decorative).
  4. The logo is the ONLY label for an action/row? -> set `label` for a11y.
  5. Need EVERY logo available (not just the built-in ~29)? -> load the opt-in observeops-logos bundle once; then any of the 445 `names` renders.

Usage rules

os
Use when: labelling an OS monitor/host (Linux/Windows/…)
Don't: a monochrome OS glyph is needed (use obs-icon)

cloud
Use when: a cloud provider / service monitor
Don't: a generic 'cloud' UI icon (use obs-icon cloud)
e.g. an AWS EC2 monitor row
database
Use when: a database monitor (MySQL/Postgres/Mongo…)
Don't: a generic database glyph
e.g. a MySQL instance in a monitor list
fallback
Use when: the type is unknown or not bundled — obs-logo shows `no-icon` so layout never breaks
Don't: relying on it for a common type (add it to CURATED)
e.g. an unrecognised monitor type → the neutral placeholder
