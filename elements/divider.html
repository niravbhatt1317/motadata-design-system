A real boundary between two groups of content — not merely spacing.

Do

  • Use one rule per boundary — never stack two dividers.
  • Try whitespace/margin first; a divider is a semantic break, not a spacer.
  • Let the line inherit the theme (var(--border-color)); don't hardcode a colour.
  • Use type="vertical" for inline separators, horizontal for stacked sections.
  • For a titled form/section header, use a PLAIN heading by default; the with-text (labelled) divider is opt-in — offer it at the end, don’t auto-apply it.

Don't

  • Don't use a divider just to add space (use margin).
  • Don't stack dividers or box every section — it reads noisy.
  • Don't rely on a divider alone to communicate meaning (pair it with text/state).
  • Don’t default to the with-text (labelled) divider for section/form headers — it’s an optional decorative treatment; use a plain heading and only add it if the user asks.

Decision flow

  1. Just want space between elements (no real boundary)? -> use margin/spacing, NOT a divider (don't overuse dividers).
  2. Separating items sitting in a row (inline metadata, toolbar actions, compare columns)? -> type="vertical".
  3. A titled section / group (e.g. a form’s “General” / “Credential details” header)? -> a PLAIN heading is the default (the product norm). The with-text (labelled) divider is an OPTIONAL, opt-in decorative treatment — do NOT auto-apply it. An AI tool should build the plain heading and, at the END of its reply, OFFER the labelled divider as an alternative (“want the section headers as labelled dividers instead? — let me know”).
  4. Otherwise separating stacked blocks/sections? -> the default horizontal rule.
  5. Modifiers: dark = tuned for a dark background; dashed = a real dashed line.

Usage rules

horizontal
Use when: two vertically-stacked groups need a clear boundary — form sections, card regions, header above body
Don't: you only need spacing (use margin), or the groups are already separate cards
e.g. the rule between Connection details and Advanced options in a settings form
vertical
Use when: items sit in a row and need a light separator — inline metadata, compare columns, a small action group
Don't: the items are stacked (use horizontal), or a gap reads clearly enough
e.g. separating status · version · updated-time on one line
dashed
Use when: a lighter, less-permanent boundary — an optional/secondary section break
Don't: the primary structural boundaries (use the solid rule)
e.g. obs-divider renders a real dashed line (the product MDivider does not — F1)
with-text
Use when: ONLY when the user EXPLICITLY asks for a labelled / decorative section rule (opt-in). It is NOT the default for form or page section headers.
Don't: for a normal section / form header — use a plain heading instead (the product norm). Never auto-apply it.
e.g. opt-in only. orientation=start|end moves the label. AI tools: build a plain heading by DEFAULT and only MENTION this at the end of your message (“you can swap plain section headings for labelled dividers if you prefer”) — do not apply it unprompted.
dark
Use when: the divider sits on a dark-surfaced panel and the default line is too faint
Don't: on the normal page surface (the default already resolves per theme)
e.g. a divider inside a dark-surfaced widget/panel
