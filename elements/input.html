Capturing typed input (text/number/search/multi-line) on a form or toolbar.

Do

  • Wrap inputs in FlotoFormItem for label + validation (standard form pattern).
  • Pick the type for the data; bind with v-model.
  • Use prefix/suffix for context icons; addonBefore/addonAfter for units/protocols.

Don't

  • Don't rely on @input to update the model — it's @update (F1).
  • Don't use the placeholder as the only label.
  • Don't expect a password show/hide toggle from type=password (F2).

Decision flow

  1. Multi-line text? -> type=textarea (or FlotoFormItem type=textarea).
  2. Numeric value (with steppers)? -> type=number (MInputNumber).
  3. Secret/password? -> type=password (PasswordInput for show/hide).
  4. Search box (enter/clear, emits search)? -> type=search (MInputSearch).
  5. A date/time? -> date picker, not a text input.
  6. Otherwise single-line text -> type=text (default).
  7. [Field] In a form with a label/validation? -> wrap in FlotoFormItem (the norm).
  8. [Style] Dense/inline underline look? -> .material-input. Unit/protocol attached? -> addonBefore/addonAfter. Context icon? -> prefix/suffix.

Usage rules

text
Use when: single-line free text (name, label, value)
e.g. monitor name
password
Use when: secret entry
Don't: when a show/hide toggle is needed (use PasswordInput) — type=password has none (F2)
number
Use when: numeric input with steppers
e.g. port, threshold, interval
search
Use when: a search box (Enter emits search, has an enter button)
e.g. filter/search a list
textarea
Use when: multi-line text
e.g. description, notes
prefix/suffix
Use when: a context icon inside the field (search glass, unit)
e.g. search prefix, $ suffix
addonBefore/addonAfter
Use when: attached fixed segments (protocol/unit)
e.g. https:// … .com
material-input
Use when: a dense/inline Material underline look (bottom border only)
e.g. inline filters/toolbars (62x)
allow-clear
Use when: an optional field/search where clearing to empty is valid
e.g. filter/search inputs (x to clear)
error-state
Use when: a field fails validation
disabled-vs-readonly
Use when: disabled = can't interact (greyed); read-only = selectable/copyable but not editable (view mode)
FlotoFormItem
Use when: any input in a form — adds the label + validation (the standard pattern, 1783x)
no-border-input
Use when: A borderless field for inline editing — no visible box until interacted with, so the value reads like plain text in place. Rare (3x); use only where the field lives inside a larger surface and a border would add visual noise.
Don't: Don't use for normal form fields where users need to see the editable affordance — use the default bordered text input, or .material-input for a dense-but-visible underline. Reserve no-border for true inline-edit-in-place spots.
e.g. An inline-editable label/title edited directly in place (e.g. renaming an item where the value sits inline, no form box), one of the ~3 borderless inline-edit spots.
autocomplete (search + suggestions)
Use when: a SEARCH field whose suggestions come from what the user TYPES (search-as-you-type) — a live suggestion list, keyboard-navigable
Don't: picking from a known fixed list (use the Dropdown picker / Select); a plain search that just filters a list shown elsewhere (use type=search with no suggestion list).
e.g. the global omnibox search, metric/counter search-ahead, host/monitor name suggestions (auto-complete-list.vue / omnibox).
