Screen regions

Inside the content panel a standard page stacks four regions top-to-bottom: Page header (required) → Toolbar / filter bar (optional) → Body (required) → Footer / pagination (optional). The body takes one of 6 content layouts — single column, two-pane, master-detail, dashboard grid, three-pane, chart-over-grid.

Compose a page top-to-bottom — header → (toolbar) → body → (footer) — then give the body one of six content layouts.

Do

  • Compose top-down: Page header → Toolbar → Body → Footer.
  • Mark required regions (Page header, Body) with the primary left accent.
  • Pick the content layout that matches the task (two-pane for tree+content, master-detail for list+record).

Don't

  • Don't omit the Page header (it's required).
  • Don't use a drawer for a panel-sized record where two-pane reads better.

Where it’s used

  • Every in-app page's content panel.
  • Two-pane → explorers, settings · Master-detail → alert/inventory records · Dashboard grid → dashboards.
  • Three-pane → metric / apm explorers · Chart-over-grid → trap viewer / log dashboards.

Decision flow

  1. Start EVERY page with a Page header (title + primary action). Then the body picks ONE content layout:
  2. A flat list of records? -> Single column (Toolbar/Filter bar + Table + pager).
  3. A tree/hierarchy on the left + detail on the right? -> Two-pane (master-detail).
  4. A list where selecting a row opens a record beside/over it? -> Master-detail (list + Drawer).
  5. Metric tiles? -> Dashboard grid. A chart above a supporting table? -> Chart-over-grid.
  6. Only escalate to Three-pane when a saved-views rail AND a picker are BOTH needed. Don't combine two content layouts on one screen.
