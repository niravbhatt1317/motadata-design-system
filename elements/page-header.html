Page Header

The list/detail PAGE HEADER at the top of a page: an optional back button + the title (--primary-alt, weight 500) + an optional count pill on the left, and right-side actions (search / export / primary Add) via the default slot, over a --border-color bottom rule. Split from the product's Toolbars family. NOT the strip above a list/table (that is obs-toolbar) and NOT between-page navigation (obs-sidebar / obs-breadcrumbs). Supports an optional subtitle, a detail-header metadata strip (meta=[{label,value,icon?,status?}] with an accent stripe — the RUM/APM span-detail header), (detail/drawer header pattern) and a breadcrumb slot (drop obs-breadcrumbs). The global app top-bar (logo/search/notifications/user) is a SEPARATE archetype, not a page-header variant.

Slots

  • default — the right-side actions — compose obs-input (search), obs-button (primary Add), icon buttons, etc.
  • back — a custom leading control, replacing the default back chevron.
  • title — extra content after the title — a status badge (obs-severity / obs-tag), e.g. the monitor detail "Up".
  • breadcrumb — a breadcrumb trail ABOVE the header row (drop obs-breadcrumbs here); the slot is invisible when empty.
  • before — content immediately BEFORE the title (a monitor-type icon / avatar).

Do

  • Use as the top bar of a list/detail page — title + count + the page’s primary actions (Add / export / search).
  • Add a back button (a left gutter, centred on the title) for a nested/detail page drilled into from a list.
  • Use a subtitle, or an accent + meta strip, for entity/detail headers (RUM/APM span detail, monitor detail); a breadcrumb slot for a trail.
  • Compose the actions from DS elements — obs-input (search), obs-button (Add / bordered secondary / [squared] icon).

Don't

  • Don’t use for a search/filter/bulk-action strip above a list or table — that is obs-toolbar.
  • Don’t use for the global app top bar (logo / notifications / user) — that is obs-app-header.
  • Don’t use for between-page navigation — obs-sidebar (primary) / obs-breadcrumbs (trail).
  • Don’t use `title` as the heading attribute (it sets a native tooltip) — use `heading`.

Where it’s used

  • The top bar of every list page — Monitors / Alerts / Alert Policies / Reports (title + count + search + primary Add). FlotoPageHeader, 54× across ~40 files.
  • Detail / nested pages — a back button + title (+ subtitle) + record actions (Edit / Export / Re-run).
  • Entity / span DETAIL headers — the RUM/APM Session · Action · Resource drill-downs and the inventory Monitor detail: accent stripe + title + a status badge + a " | "-separated metadata strip.
  • Inside a drawer/panel (with subtitle or a meta strip) — the drawer supplies its own close; page-header supplies the title + meta.

Decision flow

  1. Title + primary actions at the TOP of a page (list or detail)? -> obs-page-header.
  2. Detail / drawer header that needs a secondary line under the title? -> add subtitle="…". A location trail above it? -> the breadcrumb slot (obs-breadcrumbs).
  3. An entity/span DETAIL header with a row of attribute fields (Session/Action/Resource, monitor detail)? -> add accent="<severity>" + meta=[{label,value,icon?,status?}] (the metadata strip).
  4. A search / filter / bulk-action strip sitting ABOVE a list or table? -> obs-toolbar (not page-header).
  5. Navigating BETWEEN pages/routes? -> obs-sidebar (primary nav) or obs-breadcrumbs (the trail).
  6. Switching sibling views of the SAME page? -> obs-tabs.
  7. A widget's own title + time-range + kebab? -> the widget-header toolbar variant (obs-toolbar).

Usage rules

default
Use when: every list/detail page's top bar — the title and the page's primary actions (Add, export, search).
Don't: for a control strip that belongs ABOVE a table -> obs-toolbar.
e.g. Monitors list: title + count + Search + Export + Add Monitor.
back
Use when: a detail/nested page the user drills into from a list — give them a way back.
Don't: on a top-level list page reachable from the nav (no back target).
e.g. Monitor detail -> back to the Monitors list.
with-count
Use when: the title names a collection whose size matters (N monitors / alerts).
Don't: on a singular detail page.
e.g. Monitors (128).
no-divider
Use when: the header sits on a card/panel that already provides a bottom edge.
Don't: as the default page top bar (keep the divider).
e.g. a header inside a bordered settings card.
with-subtitle
Use when: a detail / drill-down / drawer header where a secondary line adds context (type, id, last-run).
Don't: a simple list page (title alone).
e.g. AlmaLinux 9 (CIS) / "Compliance benchmark · 214 rules · last run 2h ago" (the compliance drill-down).
with-breadcrumb
Use when: a nested page that benefits from a location trail above the title.
Don't: top-level pages.
e.g. Inventory / Monitors / web-server-01 (drop obs-breadcrumbs in the breadcrumb slot).
detail-meta
Use when: an entity/span detail header (RUM Session/Action/Resource, APM trace, monitor detail) that needs a row of attribute key:value fields under the title.
Don't: a simple list/detail page (use subtitle or nothing).
e.g. accent="up" title="Session" meta=[{icon:"globe",value:"172.20.22.2"},{label:"Environment",value:"prod"},…] — a " | "-separated strip.
padding
Use when: --page-header-padding controls the CONTENT inset only (default 8px all sides). The bottom divider always spans EDGE TO EDGE (full width) regardless of the padding.
Don't: the page content area already applies padding — then set --page-header-padding: 0 to avoid double inset.
e.g. style="--page-header-padding: 0" removes the content inset; a larger value (e.g. 16px 24px) makes a roomier header. The divider stays full-width either way.

The title is an <h4> heading — one page-header per view. The back control is a real <button aria-label="Back"> that fires `back` on click/Enter/Space (keyboard-operable). Actions in the default slot are the consumer’s own focusable controls (obs-button/obs-input) in DOM order after the title. The accent stripe and meta field ICONS are decorative (aria-hidden); meta LABELS are real text ("Label: value") so screen readers read the attribute names. A status badge (obs-tag) carries its own accessible label.

Known a11y issues

  • low The count pill ("128") is presented as plain text next to the title; if the count must be announced as a labelled figure, put it in the meta strip (label:"Monitors", value:"128") instead.
