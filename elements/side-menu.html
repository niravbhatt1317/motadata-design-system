Side Menu

The in-module SECTION navigation panel — a searchable, collapsible left menu. ONE element with a `mode` axis folding the product's four side-menu forms: sections (settings sub-nav, 20×), categories (dashboard picker, count tags), tree (Log/Topology N-level hierarchy with type icon + count badge), and list (report/saved-views flat list, optional ★ favourite). Data-driven via a recursive `items` model; optional top segmented `tabs` + a search box. The active leaf highlights --primary on --code-tag-background-color (sections adds a --primary left rule). NOT the module rail (obs-sidebar), NOT sibling views (obs-tabs), NOT the faceted checkbox filter (a vertical Filter). SIZING: the element is width:100% (fills its container) — set the container WIDTH per mode (sections ~15% / categories ~30vw / tree|list ~20%); see `sizing` + usageRules[mode].width.

Slots

  • tabs-action — an action to the right of the tabs (e.g. a ＋).
  • search-action — an action to the right of the search (e.g. a layout toggle).
  • logo — optional branding/header slot at the very top (a logo or section title) — adds no height when unused.
  • default — the default (footer) slot at the bottom, below the list — e.g. a "+ New Category" action. Adds no height when unused.

Do

  • Render it as a flush WHITE panel (it uses --common-widget-bg) filling its column — don’t put it on a gray surface or in a rounded card.
  • Pick the `mode` for the shape of your data (sections/categories/tree/list).
  • Feed a recursive `items` model; set `active` to the current leaf; child items may carry an `icon`.
  • Reuse the header slots for mode chrome — `tabs-action` (＋), `search-action` (toggle); the search is a real obs-input.
  • Wire `select` to filter the grid/route; `tab`/`search` as needed.
  • Set the panel WIDTH via your layout column — the element is width:100%. In the product these are resizable panes (Settings ~15%, Dashboard ~30vw, explorers ~20%); don't hardcode a fixed px unless your layout is fixed.

Don't

  • Don’t give the side menu a gray background or a rounded/bordered card — it’s a flush white panel (product = background:none, radius:0).
  • Don't use it for top-level modules (obs-sidebar) or sibling views (obs-tabs).
  • Don't use it as a faceted checkbox filter — that's a vertical Filter.
  • Don't hand-roll the accordion/tree — reuse obs-side-menu.
  • Don't hardcode colours — active is --primary on --code-tag-background-color.

Decision flow

  1. Navigate SECTIONS within a module (Settings sub-nav; expand to sub-items)? -> obs-side-menu mode="sections".
  2. A category picker with COUNTS (Dashboard categories → dashboards)? -> mode="categories".
  3. An N-level HIERARCHY with type icons + counts (Log types, Topology tree)? -> mode="tree".
  4. A flat LIST of saved views / reports (optional favourites)? -> mode="list".
  5. Switch between top-level MODULES? -> obs-sidebar, NOT the side-menu.
  6. Switch between sibling VIEWS of the same page? -> obs-tabs.
  7. A faceted CHECKBOX filter panel? -> a vertical Filter (Filters family), not a side-menu.

Usage rules

sections
Use when: an in-module section nav that expands to sub-items (Settings-style)
Don't: top-level module switching (obs-sidebar) or sibling views (obs-tabs)
e.g. Settings: General / Monitoring / Users & Roles → sub-items, Monitoring expanded
categories
Use when: grouped items with counts, expand to children (dashboard picker)
Don't: a flat list (use list) or a deep hierarchy (use tree)
e.g. My Favorite (7) / Server (6) → child dashboards
tree
Use when: a multi-level hierarchy where nodes carry a type icon + a count (log types, topology)
Don't: a 2-level section menu (use sections/categories)
e.g. Syslog 57.25M / Linux 9.86M → Linux Syslog 9.61M
list
Use when: a flat list of saved views / reports, one active, optional favourites
Don't: when items nest (use tree/sections)
e.g. All Reports (active) · ★ Favorites · user categories
with-tabs
Use when: the panel switches between named scopes (Dashboard/NOC, Metric/Log/Flow)
Don't: a single-scope menu (omit tabs)
e.g. Metric / Log / Flow / Trap / Audit tabs above a saved-views list
with-search
Use when: the list is long enough to need filtering (default on)
Don't: a short fixed menu (set search=false)
e.g. typing 'linux' filters + auto-expands the tree
surface
Use when: always — the in-module side menu is a FLUSH WHITE panel (var(--common-widget-bg)); it fills its column edge-to-edge.
Don't: a gray/tinted surface or a rounded bordered card. Do NOT wrap it in a gray container, and do NOT set its background to --page-background-color / --common-main-bg (those are the PAGE, which is grey in a real app — the menu would go gray).
Must: keep it white and flush with a RIGHT divider only (border-right) — no card border/radius. Matches the product settings menu (full-height column separated from content by a right border).
e.g. <obs-side-menu mode="sections" items="..."></obs-side-menu> in a full-height left column — white, borderless.
