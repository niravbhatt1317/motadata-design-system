Metric List

The DS metric / KPI list (obs-metric-list) — the product's vertical-value-grid. Each row is a PROMINENT value (a large number + a unit, right-aligned) followed by its label; no column header. Used by dashboard metric / KPI widgets. NOT a data table (it only shares the grid chrome) — for rows-of-records use obs-table.

Dataset
PropTypeDefault
items
[[value, unit, label], …] or [[value, unit, label, color], …] or [{value, unit, label, color?}] — JSON string or a JS array. `color` is a --severity token (e.g. "--severity-critical") that colours the value (the product ColorCodedCell threshold colouring).
string|array—

Tokens used

  • --border-color
  • --neutral-light
  • --page-text-color

Do

  • Use for dashboard KPI / metric widgets (availability, throughput, latency).
  • Give each item a value + unit + label.
  • Colour a threshold value with a --severity token (the item's 4th field / `color` key), never a hex.

Don't

  • Don't use for tabular records (use obs-table).
  • Don't use for a record's key/value detail (use obs-key-value).

Decision flow

  1. Showing a few prominent metrics/KPIs (a big number + unit + label each)? -> Metric List.
  2. Rows of records with columns? -> the Table (obs-table).
  3. Label→value pairs describing ONE record? -> Key-Value (obs-key-value).

Usage rules

metric-list
Use when: a small set of headline metrics/KPIs, each a big value + unit + label
Don't: for tabular records (obs-table) or key/value record detail (obs-key-value)
e.g. a dashboard widget: 99.98% Availability, 1.2 k/s Requests, 142 ms p95 latency
color-coded
Use when: a metric's value should signal severity/threshold state (over budget, critical, healthy) — pass an optional `color` (a --severity token) as the 4th item field or object key
Don't: don't hardcode a hex — always a --severity token; don't colour a value that has no threshold meaning
e.g. CPU 94% in --severity-critical (red), Memory 61% in --severity-warning, Disk 12% in --severity-clear (green)

A borderless table of value/label rows; ensure the value+unit reads as one figure. Consider a <dl> if it's semantically key/value.
