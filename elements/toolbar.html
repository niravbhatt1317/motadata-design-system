Toolbar

The control strip that frames a LIST/TABLE or a widget. Three compositions via `variant`: grid (default) — a strip ABOVE a grid with search (start slot) on the left and filter / column-chooser / primary Add (default slot) on the right; bulk — the floating SELECTION pill (a clear checkbox + "N items selected" + a divider + the bulk actions), shown once rows are selected, emits `clear`; widget — a widget header (title + a time-range pill + a kebab of actions) with rounded-top chrome. NOT the page title bar (obs-page-header) and NOT the global top bar (obs-app-header). Compose the contents from DS elements (obs-input, obs-button, obs-checkbox, obs-icon, obs-select).

Slots

  • start — (grid) the left-side content — typically the search field (obs-input type=search).
  • default — the main content on the right (grid: filter/column/Add) · (bulk) the bulk action buttons · (widget) the time-range pill + kebab.

Do

  • Use variant=grid for the search/filter/column/Add strip above a list or table.
  • Use variant=bulk for the floating selection bar (checkbox + count + primary/danger actions); wire `clear` to reset selection.
  • Use variant=widget for a dashboard widget header (title + time-range pill + kebab).
  • Compose the contents from DS elements — obs-input (search), obs-button (Add / bulk actions), obs-checkbox, obs-icon, obs-select/obs-menu (filter/column popovers).

Don't

  • Don’t use for a page title bar (title + page actions) — that is obs-page-header.
  • Don’t use for the global app top bar (logo / notifications / user) — that is obs-app-header.
  • Don’t hand-build the search box or action buttons — reuse obs-input / obs-button.
  • Don’t keep the bulk bar visible when nothing is selected — render it only while count > 0.

Decision flow

  1. A search / filter / column / Add strip ABOVE a list or table? -> obs-toolbar (variant=grid, the default).
  2. A floating bar that appears once rows are SELECTED (N selected + Acknowledge / Assign / Delete)? -> obs-toolbar variant=bulk.
  3. A widget's own header (title + time-range + a kebab of widget actions)? -> obs-toolbar variant=widget.
  4. The page's title + primary actions (not tied to a list)? -> obs-page-header, NOT toolbar.
  5. The global app top bar (logo / notifications / user)? -> obs-app-header.
  6. The column show/hide dropdown itself? -> the Dropdown (obs-select) column-chooser mode, composed behind the column button.

Usage rules

grid
Use when: any list/table page needs search + filters + column show/hide + a primary Add above the grid.
Don't: for the page title bar -> obs-page-header.
e.g. search (left) + filter + the column chooser (eye = obs-select column mode: show/hide + drag-reorder columns) + Add Monitor (right), above the Monitors grid.
bulk
Use when: the user has selected rows and needs to act on the selection.
Don't: as a permanent toolbar (it appears only while rows are selected).
e.g. "3 items selected" + Acknowledge · Assign · Delete (danger) · More.
widget
Use when: a dashboard widget/card needs its own header (title + window + actions).
Don't: for a page or list header.
e.g. "CPU Utilization" + a 24h time pill + a ⋮ of Edit / Clone / Full Screen / Share / Export.
bulk-single
Use when: the bulk selection bar with exactly ONE row selected — it reads “1 item selected” (singular)
Don't: nothing selected (hide the bar) or >1 (plural “N items selected”)
e.g. variant="bulk" count="1" → “1 item selected”

The bulk bar is a role=toolbar with an aria-label ("Bulk actions"); the clear checkbox is a real obs-checkbox (keyboard-operable, fires `clear`); the count is plain text ("N items selected"). Grid/widget toolbars are plain strips — their contents (obs-input/obs-button) carry their own semantics. The divider is decorative (aria-hidden).
