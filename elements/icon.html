Icon

The reusable icon element (<obs-icon>) — renders a real product glyph from the shared library (_icons.js, extracted from src/assets/icons/icons.js; ~635 glyphs) by `name`. Accepts kebab (chevron-double-left) or camelCase (chevronDoubleLeft). Reactive: change `name` and the glyph swaps. Inherits the surrounding text color (currentColor) and takes a px/CSS-length `size`. Renders per-icon fill-rule/clip-rule, so glyphs with holes/overlaps (e.g. the theme-auto half-circle) draw correctly. Decorative by default; pass `label` for an accessible name. This is how any icon should be used across the DS — never hand-drawn/inlined SVG.

Tokens used

  • currentColor (inherits --page-text-color / the surrounding text color)

Do

  • Use <obs-icon name="…"> for every icon — it guarantees a real product glyph and one source of truth.
  • Let it inherit color (currentColor) from the surrounding text; wrap in a coloured span to recolor.
  • Give interactive/standalone icons a `label`; leave decorative ones unlabelled (aria-hidden).
  • Name in kebab (chevron-double-left) OR camelCase (chevronDoubleLeft) — both resolve; find names on the Assets → Icons page.

Don't

  • Hand-draw or inline a one-off <svg> — if a glyph is missing, add it to _icons.js from the product icons.js.
  • Hardcode a colour on the icon — drive it via the text color so it themes correctly.

Decision flow

  1. Any monochrome GLYPH (search, chevron, status, action icon)? -> obs-icon name="…" — never a hand-drawn / inline <svg>.
  2. A brand or monitor-type LOGO (Motadata / Citrix / Router / Docker…)? -> obs-logo, NOT obs-icon (obs-icon is monochrome/currentColor).
  3. A coloured severity indicator/dot? -> obs-severity (it carries the colour); obs-icon inherits the text colour.
  4. Icon NAME format? -> kebab (chevron-double-left) OR camelCase (chevronDoubleLeft) both resolve; browse names on the Assets → Icons page.
  5. Glyph missing from the set? -> add it to src/assets/icons/icons.js (build-icons.mjs regenerates _icons.js) — do not inline a one-off SVG.
  6. A glyph with holes/overlaps rendering filled-in? -> it needs even-odd; the icon data carries `fr:"evenodd"` and obs-icon applies fill-rule/clip-rule automatically.
  7. Decorative vs meaningful? -> leave decorative icons unlabelled (aria-hidden); give a standalone / interactive icon a `label` (→ role=img).

Usage rules

lock-glyphs
Use when: a padlock pair: PRIVATE/locked → lockAlt (closed, with keyhole); PUBLIC/unlocked → lockOpen (open padlock, added in the product 48×48 style; aliases: unlock, lockOpenAlt). `locks` is a closed padlock without a keyhole.
Don't: unlockAlt for "unlock/open lock" — it DRAWS AN UNDO / rotate-left arrow, not a lock (aliased as `undo`/`rotateLeft`). For an open lock use lockOpen.
Must: pair lockAlt (private) with lockOpen (public); never use unlockAlt to mean unlocked.
e.g. private → <obs-icon name="lockAlt">; public → <obs-icon name="lockOpen">; undo action → <obs-icon name="undo">
