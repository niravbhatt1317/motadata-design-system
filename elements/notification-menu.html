The top-right notification control of the app shell — the bell with an unread count that opens recent alerts/system notifications with tabs and a scrollable list. One per app chrome.

Do

  • Place it in obs-app-header's action area (next to search / before the user menu).
  • Keep `count` in sync with real unread; wire `clear` + `viewall` to your flows.
  • Tag each item with a `tab` and a `severity` so it colours + filters correctly.
  • Handle the empty state (empty-text).

Don't

  • Don't use it as a generic action menu — that's obs-menu.
  • Don't cram a full notification centre in the popover — route long/interactive lists to an obs-drawer.
  • Don't rely on the severity colour alone — the text carries the meaning too.

Decision flow

  1. The header bell + notification panel (alerts/system, unread badge)? -> obs-notification-menu, in the obs-app-header action area.
  2. The header account control (avatar -> profile/theme/logout)? -> obs-user-menu, NOT the notification menu.
  3. Streams of different kinds (Alerts vs System)? -> tabs="Alerts,System" and tag each item with a `tab`.
  4. Only one stream? -> tabs="Notifications" (or one label) -> a flat list, no tab strip.
  5. A very long / interactive notification centre? -> open it in an obs-drawer instead (route-away); this element is the compact popover.
  6. Colour a row by severity? -> item.severity (critical/major/warning/clear/up/…) drives the LEFT accent bar via --severity-<name>.
  7. Classify a row's source/type at a glance? -> item.tag renders a right-side chip (Trap / Threshold / Anomaly).
  8. Show backlog size per stream? -> give each tab a `count` (or let it compute from items) → 'Alerts (191)'.
  9. Panel overflowing the right edge? -> placement="bottom-start" anchors it left of the bell.

Usage rules

default
Use when: the standard header notification dropdown — a bell + badge, Alerts/System tabs, recent items, View all / Clear all
Don't: for a generic action menu (obs-menu) or the account menu (obs-user-menu)
e.g. obs-app-header action area: 3 unread -> Alerts (critical/major/…) + System tabs
single-list
Use when: there is only one notification stream and tabs add no value
Don't: you have genuinely distinct streams (use tabs)
e.g. tabs="Notifications" -> one flat list
empty
Use when: always handle the empty state — a tab with no items
Don't: never leave an empty panel blank
e.g. empty-text="You’re all caught up"
severity-coded
Use when: the stream is alerts and severity is the primary signal — colour the left accent bar per row
Don't: purely informational system messages with no severity (leave severity unset → a neutral bar)
e.g. items=[{severity:'critical', text:'trap alert', …}] → a red left bar
with-tags
Use when: the source/type of a notification matters at a glance (Trap, Threshold, Anomaly)
Don't: when the title already says it — an extra chip is noise
e.g. items=[{text:'trap alert', tag:'Trap'}] → a small chip on the right
with-counts
Use when: the product default — show the backlog size on each tab so users see volume before opening
Don't: counts are unknown or misleading (omit the tab `count`)
e.g. tabs=[{label:'Alerts',count:191},{label:'System Notification',count:1822}]
placement-start
Use when: the bell is positioned so a right-aligned panel would overflow — anchor it left
Don't: the standard top-right chrome (bottom-end is correct there)
e.g. placement="bottom-start"
