Timeline Scrollbar

The temporal navigator bar — batch (« ») and single-step (‹ ›) controls around a START–END time window of bucketed snapshots. Emits `shift {direction,batch}`; the consumer moves its window. Part of the Playback & Timeline family. Watch the console (shift events) as you click.

Under a temporal chart/table whose data is bucketed into fixed windows — the user steps the visible window backward/forward one point or one whole batch at a time.

Do

  • Place it directly under the temporal chart/table it scrubs (the top rule reads as the divider).
  • Wire `shift` to move your data window (single point vs whole batch via the `batch` flag).
  • Show the current window's start/end in `start`/`end`.
  • Disable it while loading or at the range boundary.

Don't

  • Don't use it to select an absolute date/range — that's obs-date-time-picker.
  • Don't use it to rotate dashboards — that's obs-noc-player.
  • Don't hardcode colours — it uses --border-color / --neutral-lightest / --neutral-lighter.

Decision flow

  1. Step a bucketed TIME WINDOW back/forward under a temporal chart/table? -> obs-timeline-scrollbar.
  2. Pick an absolute date or a relative preset range? -> obs-date-time-picker, NOT this.
  3. Rotate through DASHBOARDS on a countdown (wallboard)? -> obs-noc-player.
  4. Single point vs whole window? -> the single chevron emits batch:false (one point); the double chevron emits batch:true (a whole window).

Usage rules

default
Use when: the data is bucketed into fixed windows and the user steps the visible window backward/forward
Don't: for absolute date/range selection (that is obs-date-time-picker)
e.g. under the netroute history chart: « ‹ Jul 21 06:00 PM … 06:15 PM › »
disabled
Use when: data is loading, or the window is already at the earliest/latest available bucket
Don't: as a permanent read-only display — if it never steps, it should not be shown
e.g. disabled while the history query is in flight
