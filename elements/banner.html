Banner

An inline notice / callout — a tinted surface with a status icon and a message. Intents: info (default, NEUTRAL), note (blue), success, warning, error. Persistent and in-flow — not a transient toast, not a blocking modal.

Do

  • Use obs-banner for a persistent inline notice; pick the variant by intent (info default).
  • Keep the message short; put a lead-in in `title` and the detail in the slot.
  • Let the colours come from the tokens (info-* / severity-*) — never hardcode.

Don't

  • Don't use a banner for transient post-action feedback (that's a toast) or for a blocking choice (that's obs-modal).
  • Don't reuse an off-purpose token for the surface — obs-banner uses --info-surface (info) / --primary-alt-lighter (note) / severity surfaces.
  • Don't stack many banners; one notice per surface.

Decision flow

  1. A persistent message tied to a section / form (a hint, a visibility notice)? -> obs-banner (variant by intent).
  2. A transient, auto-dismissing message after an action (saved/deleted)? -> a toast, NOT obs-banner.
  3. A blocking decision the user must answer? -> obs-modal (confirm), NOT obs-banner.
  4. Just a destructive-action warning inside a form? -> obs-banner variant="error" (inline), not a modal.

Usage rules

info
Use when: the DEFAULT low-key notice — neutral surface + muted grey-blue text (--neutral-lightest / --neutral-regular).
Don't: when you need emphasis — use note; for success/failure use success/error
e.g. 'Anyone in the organization can view this dashboard. Edit access is limited to you and Dashboard Admins.'
success
Use when: a positive inline confirmation that should persist on the surface
Don't: for transient post-save feedback — that's a toast
e.g. 'Sharing updated — 3 users can now view this.'
warning
Use when: a non-blocking caution the user should read before acting
Don't: for a hard block — use obs-modal
e.g. 'This category is shared with 20+ users.'
error
Use when: an inline error/destructive notice kept in context
Don't: for a blocking decision — use obs-modal (confirm)
e.g. 'At least one user is required when Private.'
closable
Use when: the notice is dismissible and not essential to keep on screen
Don't: for a notice that must stay (a permanent form hint)
e.g. closable → user can dismiss a one-time tip
note
Use when: an emphasised BLUE callout (blue bg + blue icon) that should stand out more than the neutral info.
Don't: for a routine notice (use info) or for status feedback (success/warning/error)
e.g. a highlighted 'note' or tip that needs more attention than the default info
