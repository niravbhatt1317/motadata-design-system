Breadcrumbs

The location TRAIL (+ an optional back chevron): a path of crumbs (Reports / Compliance / PCI-DSS Audit) with the current (last) crumb in weight 500 and the ancestors as muted links. Shows where the user is and gives a one-click way up one or many levels. Data-driven `items`; separator is `/` (default) or a chevron. Lives in a page header (obs-page-header has a `breadcrumb` slot). NOT module switching (obs-sidebar), NOT sibling views (obs-tabs), NOT a graph-expansion trail.

Do

  • Feed the path via `items`; the last item is automatically the current (bold) crumb.
  • Wire `navigate` (ancestor click) and `back` to your router.
  • Drop it in obs-page-header's `breadcrumb` slot for a page location bar.
  • Keep crumb labels short; the current crumb ellipsises if long.

Don't

  • Don't use breadcrumbs to switch modules (obs-sidebar) or sibling views (obs-tabs).
  • Don't put actions in the trail — a trail is location, not commands.
  • Don't make the current (last) crumb a link — it's the page you're on.
  • Don't hardcode colours — the ancestors are --neutral-light, the current is --page-text-color.

Decision flow

  1. Show the user's LOCATION plus a way up one or MANY levels? -> obs-breadcrumbs (the trail).
  2. Only need to go BACK one level (a chevron before a title)? -> obs-breadcrumbs with `back` and a single crumb (the back-button atom).
  3. Switch between top-level MODULES? -> obs-sidebar, NOT breadcrumbs.
  4. Switch between sibling VIEWS of the same page? -> obs-tabs.
  5. Put the trail at the top of a page? -> drop obs-breadcrumbs in obs-page-header's `breadcrumb` slot.
  6. A graph node-expansion trail? -> that's a graph-breadcrumb, a different navigator.

Usage rules

trail
Use when: a nested page needs to show its path and let the user jump up any level
Don't: a flat top-level page (no hierarchy to show), or for actions (a toolbar holds actions)
e.g. Reports / Compliance / PCI-DSS Audit — with PCI-DSS Audit as the current crumb
with-back
Use when: a detail page where a quick way back is as important as the trail
Don't: the top-level list (nowhere to go back to)
e.g. a back chevron + Inventory / Monitors / web-server-01
chevron-separator
Use when: the design uses › between crumbs instead of /
Don't: when the product's default / is expected
e.g. Home › Monitors › web-server-01
back-button
Use when: the user only needs to go back one level (the smallest nav atom)
Don't: when they need to see where they are or jump multiple levels (use the full trail)
e.g. a chevron-left before a detail-page title (FlotoBackButton)
divider
Use when: the breadcrumb acts as a page-header LOCATION bar and needs a bottom rule to separate it from the content (e.g. the compliance header)
Don't: an inline trail inside page content (no rule needed)
e.g. divider → a --border-color bottom rule under the trail
