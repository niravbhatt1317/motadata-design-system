# Chart fixtures

Sample data used by the Elements site, the Storybook stories and the chart verification
harness. One file per chart variant.

## Provenance

These are **not hand-invented**. Each fixture was captured from a real rendering of the host
application and then passed through `scripts/sanitize-fixture.mjs`. Capturing rather than
inventing is deliberate: the fixtures carry the real array shapes, point counts, axis ranges and
resolved visual configuration, which is what makes a side-by-side comparison meaningful. A fixture
someone made up would prove nothing.

## What the sanitiser guarantees

Every fixture in this directory has been stripped of host, entity and metric identifiers, and of
runtime state. Series names are rewritten to generic hosts (`web-01 · avg`). Numeric data, array
shape and point counts are preserved unchanged.

`scripts/sanitize-fixture.mjs` fails closed: it refuses to emit a file that still contains a
denied key or an IPv4-shaped string.

## `«fn»` markers

A chart configuration contains functions — tooltip formatters, axis label formatters, event
handlers. Those cannot survive JSON, so they are replaced with the marker `"«fn»"`.

This means a fixture records **that** a formatter existed at a given path, but not what it did.
Formatter behaviour is therefore **not** covered by the configuration diff and must be verified by
rendering — this is a known limit of the config-diff gate, not an oversight.

## Shape

```jsonc
{
  "$fixture":    "chart-line",
  "$provenance": "captured from a host rendering, then sanitised",
  "$note":       "\"«fn»\" marks a function that could not be serialised.",
  "config":      { /* chart, colors, xAxis, yAxis, tooltip, legend, plotOptions, series, … */ }
}
```

## Regenerating

Fixtures are regenerated by capturing from a running host instance and re-running the sanitiser.
The capture step needs a live host application and is therefore a manual, local operation — it is
not part of CI. See the internal design record for the capture procedure.
